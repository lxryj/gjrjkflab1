# 测试样例、过程与结果

## 如何运行

在项目根目录安装依赖后执行：

```text
npm ci
npm test
```

`npm test` 先运行项目本地 TypeScript 编译器，构建成功后用 Node.js 的 `assert/strict` 执行功能断言。每个场景创建独立的 Cli 实例；文件 IO 场景使用独立系统临时目录，结束后清理。当前有真实失败用例，因此退出码为 **1**；只有构建和全部断言通过时才返回 **0**。没有将已知缺陷跳过或转成“预期通过”。

## 文件说明

| 路径 | 内容 |
|---|---|
| `run.cjs` | 构建、场景隔离、过程采集、报告生成及失败退出码。 |
| `cases.cjs` | 按需求编写的正常流程、边界及错误场景；每例有编号、需求依据和断言，失败例关联 Q1–Q9。 |
| `fixtures/*.svg` | 原说明示例、缺失 id、重复 id、交错绘制顺序及损坏 XML 的固定输入。 |
| `fixtures/flowchart.cli` | 原说明 6.1 双节点流程图的完整命令回放；包含一次预期的 IO 后 undo 错误。 |
| `fixtures/errors.cli` | 重复 id、对象不存在、参数错误等错误命令，检查失败后仍可继续会话。 |
| `PROCESS.md` | 本次测试步骤、结果、缺陷及验证边界。 |
| `results/report.md` | 自动生成的逐例汇总、成功/失败数量和失败原因。 |
| `results/report.json` | 所有场景的命令输入、实际输出、断言错误、时长、环境、Git HEAD 与源码 SHA-256。 |
| `results/build.log` | 编译命令、时间、退出码和编译输出。 |
| `results/repl.log`、`results/errors.log` | 实际 `dist/index.js` 子进程的终端回放输出。 |
| `results/flowchart.svg` | 流程图回放实际导出的文件，可用浏览器人工预览。 |

每次执行都会更新 `results/` 内的对应产物；需保留历次结果时，可通过 Git 提交保存。JSON 中保留的临时路径用于解释本次 IO 过程，临时文件已清理。报告中的源码哈希用于识别被测工作区版本，Git HEAD 不单独代表所有未提交修改。

## 测试依据与覆盖

| 要求 | 场景编号 | 检查重点 |
|---|---|---|
| 文档、输入及帮助 | D01–D04、E01–E03、F01–F10 | 尺寸、浮点数、引号/中文、文件路径、读写失败、导入和往返后的状态，以及自动 id 序号作用域。 |
| 六种图形与 set | S01–S12 | 每类创建、move/scale 的数值结果、in、默认样式、白名单、唯一/非空 id 和阶段边界 box。 |
| 树形结构与组合 | G01–G11 | 递归变换、组内顺序、解组、迁移、环检查、删除恢复、跨父分组。 |
| 撤销重做 | H01–H05 及 G02/G04/G07/G08 | 一条编辑一个单元、快照隔离、显示不入历史、redo 分支和 IO 锁定。 |
| 显示信息 | V01–V02 | tree 子树、几何/样式、show 父容器。 |
| 真实启动入口 | I01–I02 | 子进程从 stdin 读取完整脚本，核对提示符、正常反馈、预期错误及输出 SVG。 |
| 架构规则 | A01 | 扫描当前生产源码的普通/类型导入，对照允许依赖方向；测试代码单向调用生产代码。 |

用例会核对输出和状态，而不仅判断“没有抛异常”。部分比较以读写前后状态一致为依据；移动/缩放等关键计算另有手工确定的预期值。XML 使用 `XMLValidator` 检查有效性，并用解析后的坐标/文本作断言。依赖检查适用于当前静态字符串导入形式，不能替代未来复杂动态加载场景的人工评审。

## 最近一次结果

初始基线为 49 个场景中 40 个通过、9 个失败；tree 样式修复后为 41/49。面向对象重构与问题修复后，最新结果为严格构建通过，**50 个场景全部通过**。完整结果见 [results/report.md](results/report.md)，过程及缺陷修复记录见 [PROCESS.md](PROCESS.md)。这是对项目当前支持范围的回归证据，不代表已覆盖完整 SVG 标准或全部可能输入；继续修改后应重新运行 `npm test` 并以最新报告为准。
